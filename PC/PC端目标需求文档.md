## 1. 文档定位与范围

### 1.1 定位

本文档是 ToneUp PC Web 前端的**唯一开发依据**。安卓端需求见独立文档，本文不涉及。

层级关系如下：

1. **接口契约**：`../backend/后端目标需求文档.md` 是唯一权威的 API 契约。本文档只声明 PC 消费哪些端点，不复述请求与响应结构。任何字段名、路径、状态码、错误码发生冲突时，**一律以后端契约为准**。
2. **总体需求**：《开发需求文档》V1.1 提供产品背景、交互原则与视觉基调；其中第 9.1 节列出的正式接口名称为命名权威。
3. **数据协议**：《数据库结构文档》说明题库与用户库的数据来源。客户端只消费后端转换后的统一题目 DTO，不感知 SQLite 表结构。

### 1.2 范围

- V1 一次性支持全部题型渲染（见决策 D-01），覆盖数学一/二、英语一/二共 4 个真实题库。
- 目标运行环境：桌面浏览器（Chrome / Edge 近两个大版本），分辨率 1920×1080 与 1366×768。
- 部署形态：SPA 静态资源，后续置于反向代理之后，HTTPS 由部署侧保证。

### 1.3 不做的事

- 不实现移动端适配（窄于 1024px 只保证可用，不做重点优化）。
- 不在客户端判定任何答案的正确性，正确性、解析、掌握度、复习时间全部以服务端返回为准。
- 不直接依赖 SQLite 字段或服务器文件路径，只使用 `bank_id` 与统一 DTO。

## 2. 技术选型与工程结构

### 2.1 技术栈（固定，不得更换）

| 层级 | 选型 | 约定 |
| :--- | :--- | :--- |
| 框架 | Vue 3（Composition API + `<script setup>`） | 全部新代码使用组合式 API |
| 语言 | TypeScript（`strict: true`） | 关闭任何宽松选项；禁止 `any` 逃逸到业务层 |
| 构建 | Vite | 路由级代码分割；KaTeX、图表库独立 chunk |
| 组件库 | Naive UI | 按需引入；主题定制见第 10 章 |
| 状态 | Pinia | store 划分见 2.4 |
| 路由 | Vue Router 4（history 模式） | 路由表见 2.3 |
| 类型来源 | 后端 OpenAPI 契约生成（如 openapi-typescript） | 生成物入 `src/api/generated`，**禁止手改**；手写类型只做派生与收窄 |

### 2.2 目录结构约定

```text
PC/
├── src/
│   ├── api/
│   │   ├── generated/        # OpenAPI 契约生成的 TS 类型（构建产物，禁手改）
│   │   └── http.ts           # 统一请求封装：鉴权头、超时、取消、错误解析
│   ├── components/
│   │   ├── question-renderers/   # 题型渲染注册表 + 各题型组件（第 6 章）
│   │   ├── layout/               # 侧栏、顶栏、面包屑、抽屉
│   │   └── common/               # 富文本渲染器、懒加载图片、虚拟列表包装
│   ├── composables/          # useKeyboardShortcuts / useDraft / usePolling 等
│   ├── stores/               # auth / catalog / practice / review / stats / ui
│   ├── router/               # 路由表与守卫
│   ├── views/                # 页面级组件（与第 5 章页面清单一一对应）
│   ├── styles/               # 设计令牌、主题变量
│   ├── utils/                # KaTeX/markdown 渲染管线、sanitize、格式化
│   └── main.ts               # 启动：注册表校验（第 6 章）在此执行
└── index.html
```

### 2.3 路由表规划

| 路径 | 名称 | 页面 | 守卫 | 批次 |
| :--- | :--- | :--- | :--- | :--- |
| `/login` | login | 登录/注册页 | 已登录则跳首页 | M1 |
| `/` | home | 首页 | auth | M1 |
| `/catalog` | catalog | 题库选择页 | auth | M1 |
| `/practice/:bankId` | practice | 刷题工作台（含解析视图） | auth | M1 |
| `/review/today` | review-today | 今日复习页 | auth | M2 |
| `/wrong-book` | wrong-book | 错题本 | auth | M2 |
| `/stats` | stats | 统计页 | auth | M2 |
| `/notes` | notes | 个人笔记 | auth | M2 |
| `/ai-feedback` | ai-feedback | AI 纠错上传页 | auth | M3 |
| `/admin` | admin | 管理页 | auth + admin 角色 | M3 |
| `/:pathMatch(.*)*` | not-found | 404 兜底 | 无 | M1 |

约定：

- 刷题工作台的筛选条件（年份、题型）写入 URL query，刷新与分享可恢复现场。
- 从工作台离开且有未提交内容时，`onBeforeRouteLeave` 弹确认（FR-PRAC-11）。
- 认证失效（401）全局拦截：跳转登录并记录当前路径，登录成功后回到原页面。

### 2.4 Pinia store 划分

| Store | 职责 | 持久化策略 |
| :--- | :--- | :--- |
| `auth` | 令牌存取、当前用户信息（含角色）、登录/登出动作 | 令牌入 localStorage；登出/切账号时清理全部用户域缓存 |
| `catalog` | 学科/题型/题库目录树、当前选择路径（面包屑数据源） | 会话级内存缓存，手动刷新 |
| `practice` | 刷题会话：筛选、题目窗口、当前索引、状态机、草稿读写、疑问标记、client_request_id 管理 | 草稿与进度实时写 localStorage（键设计见 8.4） |
| `review` | 今日复习列表、完成进度 | 内存为主，进度草稿同 practice 规则 |
| `stats` | 概览指标、薄弱项、时间范围参数 | 内存缓存 + 手动刷新 |
| `ui` | 主题（浅/暗/跟随系统）、侧栏折叠、动效开关、抽屉状态、快捷键提示开关 | localStorage |

## 4. 整体布局与导航

### 4.1 布局骨架

- **左侧导航**：宽度 240px，可折叠至 64px 图标栏（折叠状态记忆在 `ui` store）。导航项：首页、题库、今日复习、错题本、统计、笔记、AI 纠错、管理（仅 admin 可见）。
- **右侧主区**：内容最大宽度 1280px 居中；刷题工作台允许全宽分栏模式。
- **顶栏**：左侧为面包屑，右侧为用户菜单（用户名、退出、主题切换、动效开关）。
- **主题**：浅色模式侧栏使用轻量毛玻璃（backdrop-filter blur）；暗色模式使用深空灰渐变。主色与强调色见第 10 章。

### 4.2 断点行为

| 视口宽度 | 行为 |
| :--- | :--- |
| ≥1600px | 宽松三栏：侧栏展开 + 题目区 + 信息栏（知识点、笔记、进度） |
| 1280~1599px | 标准：侧栏展开 + 主区，信息并入主区右侧 |
| 1024~1279px | 侧栏默认折叠为 64px；右侧信息栏改为抽屉（Naive UI Drawer），由按钮唤出 |
| <1024px | 非目标分辨率，保证可用即可：侧栏抽屉化，信息栏抽屉化 |

### 4.3 面包屑三级联动

- 格式：`学科 / 题型 / 年份`，例如 `考研数学 / 真题 / 2024`。
- 点击任一级回退到对应选择层级，选择下级时上级保持联动（学科变化则题型与年份重置）。
- 数据源为 `catalog` store 的当前选择路径；非题库流程页面显示页面名即可。

## 6. 题型渲染注册表规范

### 6.1 注册机制

- 注册表是一个 `Record<TypeCode, Component>` 映射，键为后端契约中的 `type_code` 字符串，**逐字符一致，不得自定义别名**。
- 工作台通过动态组件挂载：`<component :is="resolveRenderer(question.type_code)" />`。
- **启动时校验**（main.ts 内执行，先于路由挂载）：
  1. 注册表键集合必须与后端契约的 type_code 枚举完全一致；
  2. 出现重复注册立即抛错并列出冲突键；
  3. 出现缺失立即抛错并列出缺失键；
  4. 开发环境校验失败阻断启动；生产环境输出 error 级日志并以降级组件兜底，保证页面其余部分可用。

### 6.2 组件职责边界（QuestionContext 契约）

所有题型组件只通过统一的 QuestionContext 接收数据与回调，**不直接调用任何 API，不感知路由与持久化**。输入合法性校验在组件内完成，提交调度统一在工作台。

| 字段 | 语义 | 说明 |
| :--- | :--- | :--- |
| `question` | 统一题目 DTO | 含 content、passage、options、sub_questions、type_code 等，字段以后端契约为准 |
| `answer` | 当前用户答案（受控读写） | 结构随题型不同：选项键、字符串、逐空数组、排序序列、长文本 |
| `readonly` | 只读态 | 已提交或复盘场景，控件不可修改但完整展示 |
| `disabled` | 禁用态 | submitting 等互斥期间禁用输入 |
| `showAnswer` | 展示正确答案 | 配合解析视图 |
| `showAnalysis` | 展示解析 | 配合解析视图 |
| `grading` | 主观题判分状态（可选） | pending/processing/succeeded/failed 及结果载荷；客观题为空 |
| `onAnswerChange(answer)` | 回调 | 答案变更上报，工作台负责草稿持久化与状态迁移 |
| `onSubmitRequest()` | 回调 | 请求提交，由工作台统一调度幂等与状态机 |

### 6.3 题型映射总表

| type_code | 适用场景 | 判分方式 | 渲染形态 | V1 状态 |
| :--- | :--- | :--- | :--- | :--- |
| SINGLE | 数学单选；英语阅读单选（READING 场景同样按单选渲染） | 服务端即时判分 | 选项组 + 可选文章面板 | 实现 |
| MULTI | 多选（当前四库暂不产生，预留扩容） | 服务端即时判分 | 复选组 | 实现（预留） |
| JUDGE | 判断（当前四库暂不产生，预留扩容） | 服务端即时判分 | 对/错二选一 | 实现（预留） |
| FILL_BLANK | 数学填空 | 双模式：服务端可即时判定则即时返回，否则转入异步判分 | 内联/集中输入框 | 实现 |

### 6.4 各题型交互细节

#### 6.4.1 SINGLE（数学单选 / 英语阅读单选）

- 选项横排展示（PC 宽屏优势），选项内容同样走公式与富文本渲染管线。
- 点击即选中并更新 answer（idle → editing）；`A/B/C/D` 快捷键等效点击。
- 英语阅读场景先渲染 passage 面板（宽屏左右分栏，窄屏上文下题），文章与题目绑定滚动不强制同步。
- Enter 确认提交；提交后进入解析视图，正确选项高亮、用户错选标红。

#### 6.4.2 MULTI（多选，预留）

- 复选交互，点击切换选中，快捷键累加切换；至少选中一项才允许提交。
- 当前四个题库不产生该类型，组件仍完整实现，保证未来扩容零改动。

#### 6.4.3 JUDGE（判断，预留）

- 对/错两个大按钮（各 ≥44px 命中区），快捷键 A/B 或 T/F 均可。

#### 6.4.4 FILL_BLANK（数学填空）

- 单行文本输入；多空题目按 sub_questions 或 content 占位顺序生成输入框，对应关系以后端契约为准。
- 支持粘贴纯文本表达式；V1 不做实时公式预览，输入框下方提示"支持纯文本表达"。
- 提交后兼容两种返回：即时判分直接进解析；异步判分走 8.2 的主观题子状态机。

#### 6.4.5 SOLUTION（数学解答）

- 多行输入区（自适应高度，约 8~20 行可见），字符计数展示。
- 提交后进入判分中状态：展示 AI 结论、逐步评语与涉及知识点；失败转自评兜底。
- 解析视图右栏展示官方 solution 与用户作答对照。

#### 6.4.6 CLOZE（英语完形填空）

- passage 面板中编号空位高亮显示；每空对应一个输入位（输入框或小选择器取决于 options 结构，以后端契约为准）。
- 支持空位间快速跳转（上一空/下一空按钮与快捷键）；答案按空序号数组保存。
- 提交后逐空标注对错，错误空位展示正确答案。

#### 6.4.7 ORDERING（英语新题型排序）

- 选项为长段落文本，采用卡片式布局，留白充足，段落完整展示不截断（可展开）。
- 排序双通道：拖拽为主，每张卡片配上移/下移按钮保证键盘可达；序号徽标实时更新。
- 提交后展示用户序列与正确序列的逐位对照。

#### 6.4.8 TRANSLATION（英语翻译）

- 左原文面板、右译文多行输入；词数统计（英文按空白分词计数）。
- 提交后异步判分：succeeded 展示评分、参考译文与批注；failed 转自评兜底。

#### 6.4.9 ESSAY（英语作文）

- 题目要求面板（词数限制等以题目原文为准）+ 大输入区；实时词数统计，接近或超出建议词数时温和提示。
- 草稿强保留：输入防抖 500ms 落盘，意外关闭后恢复时提示。
- 判分结果展示评分维度、评语与改进建议；failed 转自评兜底。

#### 6.4.10 未知题型降级

- 未注册的 type_code 渲染降级占位组件：显示该 type_code、"重试"按钮（重新拉取题目详情）与"跳过此题"入口。
- 降级绝不影响相邻题目渲染与全局导航；事件上报 error 日志便于定位。

## 7. 公式与富文本渲染方案

### 7.1 背景

- 数学题干 LaTeX 密集，行内公式以 `$...$` 包裹，另有 `$$...$$` 块级公式。
- math2 存在 markdown 残留标记（如 `### 1.`、`**bold**`）。后端负责清洗，但 PC **不得假设输入干净**，必须同时正确渲染 markdown 标记与 KaTeX 公式。

### 7.2 渲染管线

统一封装为单个富文本组件，管线顺序固定：

1. 输入原始字符串（永远视为不可信文本）。
2. markdown-it 渲染残留 markdown 标记（html 选项关闭，杜绝内联 HTML 直通）。
3. KaTeX 渲染 `$...$` 与 `$$...$$`（auto-render 扩展，errorColor 降级着色）。
4. DOMPurify 白名单过滤，允许标签限定为：`p, br, strong, em, code, pre, ul, ol, li, h1~h6, span, div, table, thead, tbody, tr, th, td, sup, sub` 及 KaTeX 生成的类节点；事件属性与 javascript: 协议一律剥离。
5. 注入 DOM。

约束：

- 题目图片不走内联 HTML，统一由 DTO 的图片标识经 `GET /api/images/{image_id}` 懒加载（见 10.6）。
- AI 返回内容（纠错结论、判分评语）永不作为 HTML 渲染，只按纯文本或受限 markdown 处理。

### 7.3 失败降级

- KaTeX 语法错误：捕获后该片段回退为原样文本展示，不影响同题其他片段。
- markdown 渲染异常：整体回退为 HTML 转义后的纯文本。
- sanitize 后内容为空：显示"内容渲染异常"占位。
- 所有渲染包裹 try/catch 且同步执行，**任何渲染失败都不阻塞切题**；超长文本折叠并提供"展开全文"。

## 8. 练习状态机与数据策略

### 8.1 状态机

每道题维护独立状态：`loading / idle / editing / submitting / submitted / error`。

| 当前态 | 事件 | 下一态 | 动作 |
| :--- | :--- | :--- | :--- |
| loading | 题目数据就绪 | idle | 渲染题干 |
| loading | 加载失败 | error | 展示重试入口 |
| idle | 用户开始作答 | editing | 启动草稿防抖写入 |
| editing | 确认且校验通过 | submitting | 固化 client_request_id，禁用输入 |
| submitting | 即时判分成功返回 | submitted | 展示解析视图 |
| submitting | 异步判分受理返回 | submitted（判分子状态机启动） | 见 8.2 |
| submitting | 网络/服务端错误 | error | 保留答案与同一 client_request_id |
| error | 重试成功 | submitted | 同成功路径 |
| submitted | 下一题 | loading（下一题） | 强制 flush 草稿 |
| 任意态 | 切题/刷新/离开 | （保存现场） | 强制 flush 草稿，必要时弹确认 |

### 8.2 主观题异步判分子状态机

主观题提交受理后，UI 呈现四级状态，状态来源以后端契约为准：

| 状态 | UI 表现 | 出口 |
| :--- | :--- | :--- |
| pending（已受理待处理） | 徽标"排队中"，可继续浏览其他题 | → processing / failed |
| processing（判分中） | 动画 + "AI 正在批改"文案 | → succeeded / failed |
| succeeded（已出分） | 展示 AI 结论、评语、知识点 | 终态（可回看） |
| failed（失败） | 展示失败原因 + **自评兜底入口** | 自评完成后终态 |

补充规则：

- 超时兜底：pending 超过 60s 未进入 processing，或 processing 超过 5 分钟未出结果，主动展示自评兜底入口（不阻塞用户切题）。
- 自评兜底界面：左栏用户作答、右栏标准答案与解析，用户给出判定（完全正确/部分正确/错误）后回传，回传方式以后端契约为准；完成后本地按自评结果更新展示与统计口径提示。
- 判分状态查询复用答题结果查询能力（`GET /api/attempts/{attempt_id}`），轮询节奏与 5.10 一致。

### 8.3 提交防重

- client_request_id 在进入 submitting 时生成并固化（UUID v4），成功或收到明确业务失败后释放。
- 网络错误重试沿用同一 client_request_id，服务端按 user_id + client_request_id 幂等去重，重复提交返回首次结果。
- submitting 期间确认按钮置灰并显示加载态；键盘 Enter 同样被拦截。

### 8.4 草稿 LocalStorage 键设计

| 键 | 值 | 写入时机 |
| :--- | :--- | :--- |
| `toneup:draft:{userId}:{bankId}:{questionId}` | `{ answer, updatedAt }` | 编辑防抖 500ms；切题/离开前强制 flush |
| `toneup:progress:{userId}:{bankId}` | `{ lastIndex, filterHash, updatedAt }` | 切题、筛选变化 |
| `toneup:marked:{userId}:{bankId}` | 疑问标记题号数组 | 标记切换 |

规则：

- 恢复提示：进入工作台检测到非空草稿时，toast 询问"检测到未完成的作答记录，是否恢复"；用户拒绝则清除该题草稿。
- 断网恢复：监听 online/offline 事件与请求失败；恢复联网后提示"网络已恢复，发现 N 条未提交记录"并逐条以原 client_request_id 重放，结果以服务端为准。
- 切账号/退出登录：清除全部 `toneup:*` 用户域键与内存缓存，防止串号。

### 8.5 缓存策略

- 题目列表内存缓存键 = 学科 + 题型 + 年份 + 其余筛选条件的哈希（filterHash）。
- LRU 上限 20 个列表会话，超出淘汰最久未用；提供手动刷新按钮强制失效。
- 元数据（catalog、题库详情）会话级缓存，管理侧重载后由用户手动刷新或重新进入页面拉新。

### 8.6 分页与预加载

- 分页参数遵循契约（page/page_size，响应含 items/total/has_more）。
- 当前题渲染完成且主线程空闲时，预取相邻题详情（`GET /api/question-banks/{bank_id}/questions/{question_id}`）。
- 预加载边界：列表接口默认不含标准答案与解析，详情预取也不会让用户提前看到答案，符合"先答后看"的产品形态；图片一律不预取。

## 10. 视觉与交互规范

### 10.1 色彩

| 用途 | 值 |
| :--- | :--- |
| 主色（深静谧蓝） | `#2B3A67`：导航、主按钮、进度环 |
| 强调色（活力紫） | `#7C3AED`：焦点环、链接、选中态、强调徽标 |
| 正确 / 错误 / 警告 | 与 Naive UI 默认语义色对齐（绿 / 红 / 橙） |
| 浅色模式 | 轻量毛玻璃侧栏（半透明 + backdrop blur） |
| 暗色模式 | 深空灰渐变背景，跟随系统或手动切换 |

### 10.2 字体与排版

- 字体栈：`Inter, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 正文行高 1.75；题干字号 ≥16px；解析 15px；行长度控制在约 40 个汉字以内换行。
- 间距采用 8px 栅格；卡片圆角 8px，控件圆角 4px。

### 10.3 微交互与动效

- 选项悬停：上浮 2px 并显示光晕；点击有明确按压反馈。
- 答错：就近轻微 3° 晃动一次（约 300ms），并给出修正引导文案。
- 动效时长区间 150~300ms：微交互 150ms、展开/抽屉 240ms、页面转场 300ms。
- 设置提供动效开关，并尊重系统 prefers-reduced-motion。
- 状态反馈同时使用文字、图标与颜色，不依赖单一颜色通道。

### 10.4 长列表

- 题号面板、错题本、笔记列表等超过约 50 条的列表启用虚拟滚动。
- 虚拟滚动容器保留原生滚动条与键盘滚动能力。

### 10.5 反馈时机

- 任何请求发出后 200ms 内必须出现 loading 态（按钮 spinner、骨架屏或进度条）。
- 成功/失败 toast 统一右上角，错误信息中文可读，开发环境附加 request_id 便于排查。

### 10.6 图片懒加载

- 题图渲染固定宽高比占位骨架，进入视口才请求 `GET /api/images/{image_id}`。
- 加载失败显示可点击的重试占位；图片容器限制最大宽度并支持点击放大查看。

## 12. 非功能性需求与验收标准

### 12.1 性能预算

| 指标 | 预算 |
| :--- | :--- |
| 首屏（登录页）传输体积 | gzip ≤ 300KB |
| 登录后首页增量 chunk | gzip ≤ 200KB（KaTeX、图表库独立分包按需加载） |
| 首页 LCP / INP / CLS | ≤ 2.5s / ≤ 200ms / ≤ 0.1（生产构建 + 本地代理环境） |
| 切题耗时（缓存命中） | ≤ 100ms，无布局抖动 |
| Lighthouse 基线（桌面模式，生产构建） | Performance ≥ 90，Accessibility ≥ 95，Best Practices ≥ 95 |

### 12.2 无障碍与人体工学

- 所有可交互控件命中区 ≥ 44×44px（题号面板格子视觉尺寸不足时用扩展命中区补足）。
- 焦点可见（focus ring 使用强调色）、Tab 顺序合理、控件具备语义化名称与屏幕阅读器可读文本。
- 连续刷题 1 小时场景下，确认/下一题等高频操作固定于主区右下操作条，鼠标流单手可达；键盘可完成完整刷题闭环。

### 12.3 流程完备性验收

以下五类场景必须在 1920×1080 与 1366×768 下全部可验证：

| 场景 | 验证要点 |
| :--- | :--- |
| 加载 | 骨架屏出现、超时有提示、不白屏 |
| 空数据 | 空态插画/文案 + 引导动作（如"去题库选题"） |
| 失败 | 中文错误分类提示 + 重试入口，重试不产生脏数据 |
| 重试 | 幂等验证：同一 client_request_id 重试不重复计次 |
| 断网恢复 | 离线续答草稿不丢，恢复后同步提示与结果以服务端为准 |

### 12.4 其他约束

- 页面无横向溢出与错位；长题干、公式、图片、解析区域可滚动且不裁切。
- XSS 防护依赖第 7 章 sanitize 白名单；令牌存储于 localStorage 的风险以此缓解，并在反代层配置 CSP 时进一步收紧。
- 构建产物带 sourcemap 但不随生产部署公开。

## 13. 开发批次建议

### M1：登录 + 布局 + 目录 + 刷题工作台全题型 + 客观题判分展示

范围：FR-AUTH 全部、FR-HOME-02/03/04、FR-CAT 全部、FR-PRAC 全部、FR-ANA-01/02/03、404 页、第 6/7/8/9 章基础设施。

验收标准：

1. 用真实 math1/math2/english1/english2 四库连续刷题 30 题，无白屏、无未捕获控制台错误。
2. 九种 type_code 全部可渲染、可作答、可提交；构造未知 type_code 显示降级卡片且可重试，不影响相邻题。
3. 客观题提交后解析分栏展示，用户答案与正确答案视觉可区分。
4. 断网作答草稿不丢，恢复后可继续；连点确认不产生重复记录（client_request_id 生效）。
5. 两种目标分辨率无横向溢出；Lighthouse 达到 12.1 基线。

### M2：主观题 AI 判分交互 + 复习错题 + 统计完善

范围：FR-ANA-04/05/06、FR-REV 全部、FR-WRONG 全部、FR-STAT-01/02/03、FR-NOTE 全部、FR-HOME-01/05。

验收标准：

1. 主观题提交后依次可见 pending/processing 状态，succeeded 展示 AI 结论与评语；failed 或超时出现自评兜底入口，并完成一次自评闭环（判定回传、展示更新）。
2. 今日复习完成一轮（含暂缓 skip）；错题本可筛选、可重练。
3. 统计页四类指标与后端数据一致；笔记可在解析视图与笔记页双向同步。
4. 判分轮询在离开页面后停止，无泄漏定时器。

### M3：AI 纠错页 + 管理页

范围：FR-AI 全部、FR-ADM 全部、FR-STAT-04、FR-ANA-07、FR-CAT-06。

验收标准：

1. 上传一张手写答案图片，任务从创建到出结果全程状态可见；失败任务可重新发起。
2. 管理页仅 admin 角色可见可进；触发目录重载后前端 catalog 刷新生效；健康检查任务结果正确展示。
3. 非 admin 访问 `/admin` 被守卫拦截并有中文提示。
4. 全量回归 M1/M2 验收项通过。
