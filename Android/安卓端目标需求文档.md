## 1. 文档定位与范围

### 1.1 定位

本文档是 ToneUp 安卓原生客户端的唯一开发依据。凡本文档与《开发需求文档.md》V1.1 冲突之处，以本文档及第 3 章决策记录为准；凡涉及接口字段、错误码、分页协议、鉴权细节，一律以 `../backend/后端目标需求文档.md` 为准，本文档只声明"消费哪些端点、怎么用"，不复述其 Schema。

主文档 §7.2 与 §7.3 中出现的旧接口路径已全部废弃，安卓端不得引用。接口命名权威为主文档 §9.1 与后端契约，完整消费清单见本文档第 13 章。

### 1.2 范围内

- 考生侧完整学习闭环：登录注册、题库浏览与选择、全题型刷题与提交、解析查看、今日复习、错题本、统计、笔记、个人中心。
- 全部 10 个题型码的渲染与作答（决策 D1），主观题 AI 异步判分交互与自评兜底（决策 D2）。
- AI 拍照纠错全流程（拍照、压缩上传、轮询诊断、结果展示）。
- 数学公式离线渲染方案及其 PoC 验证门槛（第 7 章）。

### 1.3 范围外（明确不做）

- **管理功能**：后端具备 `role=admin` 角色与管理接口，但安卓端不实现任何管理页面、管理入口或管理接口调用。管理操作属于 PC/Web 管理端的职责范围。
- 题库制作、数据导入、健康检查等运维能力。
- iOS、鸿蒙等其他移动平台。
- 离线题库包下载（题目数据始终经服务端接口获取）。

## 2. 技术选型与工程架构

### 2.1 技术栈（固定）

| 层级     | 选型                                      | 说明                                                           |
| :------- | :---------------------------------------- | :------------------------------------------------------------- |
| 语言     | Kotlin                                    | 全 Kotlin，禁用 Java 新增源文件                                |
| UI       | Jetpack Compose + Material3               | 启用 Material You 动态取色（Android 12+）                      |
| 依赖注入 | Hilt                                      | 编译期校验的注入图，见 2.4                                     |
| 网络     | Retrofit + OkHttp + Kotlinx Serialization | 统一响应外层在仓库层解包，见 2.5                               |
| 本地存储 | DataStore（Preferences + Proto）          | 用途划分见 2.6；令牌需加密存放                                 |
| 导航     | Navigation Compose                        | 单 Activity + NavHost，见 2.7                                  |
| 相机     | CameraX                                   | 仅用于 AI 拍照纠错（ImageCapture 用例）                        |
| 图片加载 | Coil（配套推荐）                          | 懒加载、占位图、磁盘缓存，服务于`GET /api/images/{image_id}` |
| 公式渲染 | WebView 封装 + KaTeX 本地资源（主案）     | 备选 Markwon + JLatexMath，详见第 7 章                         |

### 2.2 系统版本建议

**建议 minSdk 26（Android 8.0）、targetSdk 35（Android 15）。**

理由：

- minSdk 26 原生提供 `java.time`，无需核心库脱糖；覆盖当前活跃设备绝大多数；CameraX、Compose 官方支持线均在其上，兼容成本最低。
- targetSdk 35 对齐 Google Play 最新上架要求，并强制 edge-to-edge，与本项目"沉浸模式刷题 + 手势区避让"的交互设计天然一致，早适配早发现问题。

此为推荐值，若市场调研发现大量低版本用户可下调 minSdk 至 24，但需补做脱糖与权限模型适配验证。

### 2.3 工程结构（单 Module 起步）

V1 采用单 module 起步，降低构建与维护成本；通过 package 分层保持边界清晰，后续如需拆分 feature module，按 package 整体迁移即可。

```text
com.toneup.app/
├── ToneUpApp.kt              # @HiltAndroidApp Application
├── MainActivity.kt           # 单 Activity
├── ui/
│   ├── theme/                # Material3 主题、动态取色、排版
│   ├── navigation/           # NavGraph、路由常量
│   ├── components/           # 通用组件：FormulaText、QuestionRenderer 注册表等
│   └── feature/              # auth / home / bank / practice / review /
│                             # wrongbook / stats / mine / aiphoto
├── data/
│   ├── remote/               # Retrofit Service、DTO、拦截器
│   ├── local/                # DataStore、内存缓存、图片缓存配置
│   └── repository/           # 仓库实现，统一解包响应外层
└── domain/                   # 可选层：纯 Kotlin 模型与用例
```

分层约定：UI 层不直接触碰 Retrofit 与 DataStore；早期允许 ViewModel 直连 Repository，`domain` 层按需引入，不为分层而分层。

### 2.4 Hilt 注入图

| Module           | 提供内容                                                                 |
| :--------------- | :----------------------------------------------------------------------- |
| NetworkModule    | Json 配置、OkHttp（超时、日志开关、鉴权拦截器）、Retrofit 各 API Service |
| DataStoreModule  | Preferences DataStore、Proto DataStore、加密令牌存储                     |
| RepositoryModule | 各 Repository 接口到实现的绑定                                           |
| CoroutineModule  | `@IoDispatcher` / `@DefaultDispatcher` 限定符                        |

ViewModel 一律 `@HiltViewModel` 构造注入；禁止在 Composable 内直接持有仓库引用。

### 2.5 Retrofit 网络层配置要点

- Base URL 走 BuildConfig 字段，区分调试与生产环境。
- 超时：连接 10s，读取 30s；上传接口单独放宽。
- 鉴权拦截器自动附加 `Authorization: Bearer <token>`；收到 401 时清除本地会话并跳转登录页，同时保留当前页面恢复信息（路由与草稿），登录后可回到原位。
- Kotlinx Serialization 配置 `ignoreUnknownKeys = true`，后端新增字段不致客户端崩溃。
- 统一响应外层 `{success, data, message, request_id}` 在仓库层一次性解包：`success=false` 抛出携带 `message` 与 HTTP 状态码分类的业务异常（网络异常 / 参数错误 / 无权限 / 不存在 / 服务端异常），UI 层按类别展示中文提示。
- 日志拦截器仅 Debug 构建启用，且脱敏令牌。

### 2.6 DataStore 用途划分

| 存储                  | 内容                                                                                   | 说明                                                                            |
| :-------------------- | :------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------ |
| Preferences DataStore | 用户偏好：动效开关、深色模式跟随策略、上次选中的学科筛选等轻量键值                     | 读写频繁但体积极小                                                              |
| Proto DataStore       | 结构化会话数据：练习草稿、未同步提交队列、最近练习上下文（bank_id + question_id 指针） | 按 user_id 命名空间隔离，见 8.4                                                 |
| 加密存储              | 访问令牌                                                                               | 经 Android Keystore 加密后落盘（EncryptedSharedPreferences 或自封装），禁止明文 |

### 2.7 Navigation Graph 规划

```text
NavHost (单 Activity)
├── login                    # 登录
├── register                 # 注册
└── main                     # 底部四 Tab 宿主
    ├── tab_bank             # 题库 Tab（顶部为首页区块）
    ├── tab_review           # 复习 Tab
    ├── tab_stats            # 统计 Tab
    ├── tab_mine             # 我的 Tab
    ├── practice/{sessionId}?mode={practice|review}   # 刷题页（全屏）
    ├── analysis/{attemptId}                          # 解析视图
    ├── wrongbook            # 错题本（二级页）
    ├── noteEditor/{questionId}?bankId={}             # 笔记编辑
    └── aiPhoto?bankId={}&questionId={}&attemptId={}  # AI 拍照纠错流程页
```

题库选择三级联动使用半屏 ModalBottomSheet 承载，不占用独立路由（见 4.3）。Tab 间切换不重建页面状态（`saveState` / `restoreState`）。

## 4. 信息架构与导航

### 4.1 总体结构

应用采用"登录栈 + 主框架（底部四 Tab）+ 全屏二级页"三层结构。首页元素（打卡、继续上次刷题、学科快捷入口）置于"题库"Tab 顶部作为首屏形态，避免出现第五个一级入口；登录成功后默认落在题库 Tab 并直接看到首页区块。

### 4.2 底部四 Tab

| Tab | 名称 | 核心内容                                                                                      |
| :-- | :--- | :-------------------------------------------------------------------------------------------- |
| 1   | 题库 | 首页区块（连续打卡卡片、继续上次刷题按钮、学科入口列表）+ 目录浏览入口，唤起选题 Bottom Sheet |
| 2   | 复习 | 今日待复习列表（来自`GET /api/reviews/today`），支持暂缓单题                                |
| 3   | 统计 | 总览指标（正确率、刷题量、连续天数）+ 薄弱项聚合                                              |
| 4   | 我的 | 用户信息、我的笔记、设置（动效开关等）、退出登录                                              |

Tab 图标配文字标签，选中态用图标填充与颜色共同表达，不只靠颜色。

### 4.3 题库选择三级联动 Bottom Sheet

- 形态：半屏 ModalBottomSheet，高度约屏高 60%，可下拉关闭。
- 三级联动顺序固定为 **学科 → 题型 → 年份**：
  1. 第一级学科列表来自 `GET /api/catalog`；
  2. 第二级题型为所选学科的 types；
  3. 第三级年份来自 `GET /api/question-banks/{bank_id}` 返回的可用年份。
- 每级选中即进入下一级，顶部提供已选路径面包屑，点击面包屑任意一级可回退重选。
- 选定年份后底部出现"开始刷题"主按钮，创建练习会话并跳转刷题页。
- 数据缓存：catalog 当日内存缓存，支持下拉刷新；题库详情按 bank_id 缓存。

### 4.4 沉浸模式刷题

- 进入刷题页启用 edge-to-edge 并隐藏状态栏（WindowInsetsController），退出时恢复。
- 状态栏图标颜色跟随当前深浅色模式，保证隐藏前后过渡自然。
- 沉浸状态下顶部保留极简退出按钮与进度指示，避免用户迷失。

## 6. 题型渲染注册表规范

### 6.1 注册表机制与启动校验

注册表是题型插件化的核心：密封类承载稳定题型码，映射表完成到 Composable 的多态分发。

```kotlin
sealed class QuestionType(val typeCode: String) {
    object Single : QuestionType("SINGLE")
    object Multi : QuestionType("MULTI")          // reserved
    object Judge : QuestionType("JUDGE")          // reserved
    object FillBlank : QuestionType("FILL_BLANK")
    object Solution : QuestionType("SOLUTION")
    object Cloze : QuestionType("CLOZE")
    object Reading : QuestionType("READING")
    object Ordering : QuestionType("ORDERING")
    object Translation : QuestionType("TRANSLATION")
    object Essay : QuestionType("ESSAY")
}
```

规范要求：

- 注册表键为 `QuestionType`，值为 `@Composable (QuestionContext) -> Unit` 渲染函数；键名必须与服务端 `type_code` 字符串完全一致，客户端不解释数字型 question_type_id。
- 应用启动（或首次进入刷题模块）时执行完整性校验：遍历密封类全部子项，确认每个 typeCode 在注册表中恰好有一个渲染器；缺失或重复时输出包含 typeCode 的 ERROR 级定位日志（例如 `RendererRegistry missing: FILL_BLANK`），运行期以降级卡兜底，不崩溃。
- 新增题型 = 新增密封子项 + 渲染器 + 注册一行，其余代码不动。

### 6.2 QuestionContext 数据契约

所有题型组件通过统一的 QuestionContext 接收数据与回调，组件本身是纯 UI：不发网络请求、不读全局状态、不写 DataStore。

| 字段            | 类型约束           | 说明                                                                                                                                    |
| :-------------- | :----------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |
| question        | 统一题目 DTO       | 字段以后端契约为准：bank_id、question_id、type_code、content、passage（可空）、options（可空）、sub_questions（可空）、display_order 等 |
| answer          | 多态作答值         | 形态由题型决定：选项 ID、文本、按空映射、有序列表、长文本                                                                               |
| readonly        | Boolean            | 已提交或历史浏览时锁定交互，视觉上明确呈现锁定态                                                                                        |
| disabled        | Boolean            | 提交中等临时禁用，弱于 readonly 的视觉强度                                                                                              |
| showAnswer      | Boolean            | 标注正确答案（对勾 / 高亮）                                                                                                             |
| showAnalysis    | Boolean            | 展开 / 允许展开解析区                                                                                                                   |
| onAnswerChange  | (新作答值) -> Unit | 唯一的答案上行通道，组件不得自行持久化                                                                                                  |
| onSubmitRequest | () -> Unit         | 请求宿主执行提交，是否立即提交由宿主状态机决定                                                                                          |
| onToggleMark    | () -> Unit         | 收藏 / 标记回调                                                                                                                         |

### 6.3 题型清单与交互细节

| type_code   | 名称        | V1 状态                                                                    |
| :---------- | :---------- | :------------------------------------------------------------------------- |
| SINGLE      | 单选        | 必须实现                                                                   |
| MULTI       | 多选        | reserved（协议保留码，当前题库暂未出现，仍须交付基础渲染器保证注册完整性） |
| JUDGE       | 判断        | reserved（同上）                                                           |
| FILL_BLANK  | 填空        | 必须实现                                                                   |
| SOLUTION    | 解答题      | 必须实现                                                                   |
| CLOZE       | 完形填空    | 必须实现                                                                   |
| READING     | 阅读理解    | 必须实现                                                                   |
| ORDERING    | 排序        | 必须实现                                                                   |
| TRANSLATION | 翻译        | 必须实现                                                                   |
| ESSAY       | 作文 / 简答 | 必须实现                                                                   |

#### 6.3.1 SINGLE 单选

- 选项竖排卡片（安卓一律竖排，不横排），点击即时更新答案并高亮选中项，无需额外确认键即可改选。
- showAnswer 时：正确选项绿色边框加对勾图标，用户错选红色加叉号，颜色之外必须有文字或图标冗余表达。
- 支持键盘焦点遍历与 TalkBack 朗读选中状态。

#### 6.3.2 MULTI 多选（reserved）

- 点击切换选中态，可增删；底部显示已选计数。
- 需显式确认按钮提交本组选择；全部取消视为清空。

#### 6.3.3 JUDGE 判断（reserved）

- 对 / 错两枚大按钮，交互与即时更新规则同 SINGLE。

#### 6.3.4 FILL_BLANK 填空

- 单行输入框，键盘 Enter 不换行。
- 输入内容实时生成行内 LaTeX 预览（复用第 7 章渲染能力，约 300ms 节流），预览位于输入框正下方。
- 多个空（sub_questions 拆分）逐空独立输入与草稿保存；提交前逐空非空校验，留空需二次确认。

#### 6.3.5 SOLUTION 解答题

- 多行输入，最小高度 4 行，随内容自动扩展至屏幕上限后转内部滚动。
- 右下角实时字数统计（按字符计，中英文一致）。
- 草稿防抖约 500ms 自动写入，重新进入恢复并轻提示"已恢复上次草稿"。
- 提交后进入 AI 异步判分状态卡流程（FR-AN-04），failed 时给自评兜底。

#### 6.3.6 CLOZE 完形填空

- passage 折叠面板：默认收起仅显示前几行摘要，点击展开全文；长文内部滚动，绝不撑爆整页。
- 按空作答：每空一个短输入框，空序号与文中占位一一对应；提供上一空 / 下一空快捷跳转。
- 任一空有内容即计入草稿；部分空留空提交需二次确认（留空按错误计）。

#### 6.3.7 READING 阅读理解

- passage 折叠面板同 CLOZE；文章可能很长，折叠为强制行为。
- 展开状态在同一 passage 的兄弟小题之间保持，切换到不同 passage 时重置。
- 子题逐题作答，交互同 SINGLE；显示"第 x / y 小题"进度。

#### 6.3.8 ORDERING 排序

- 选项为长段落文本，列表项高度自适应，禁止截断。
- 两种排序方式并存：长按拖拽排序（默认）与序号下拉选择（无障碍友好路径，TalkBack 可完成全部操作）。
- 拖拽时被拖项抬升阴影并伴随 LIGHT_IMPACT 触感；当前顺序以序号徽标实时呈现。

#### 6.3.9 TRANSLATION 翻译

- 多行输入 + 字数统计 + 草稿保留，规则同 SOLUTION。
- 题干区与输入区上下分栏，比例可拖动调节（P1）。

#### 6.3.10 ESSAY 作文 / 简答

- 多行输入，字数统计并展示建议字数区间（元数据存在时）。
- 自动保存更激进：每次变更防抖 500ms 且每 3 秒兜底落盘一次，防止长文丢失。
- 其余交互同 SOLUTION。

### 6.4 未知题型降级

遇到注册表中不存在的 type_code 时渲染"可重试降级卡"：提示文案含原始 code（便于截图反馈）、"重试"按钮（重新拉取题目详情）与"跳过本题"。降级卡绝不崩溃，也不影响同会话其他题目渲染；同时记录埋点日志用于定位新增题型。

## 7. 数学公式渲染方案【最高技术风险】

### 7.1 风险陈述

数学题库的 content、options、solution 大量为 LaTeX（`$...$` 行内与 `$$...$$` 独立段），公式渲染质量与性能直接决定刷题体验成败。这是安卓端最高技术风险，必须在 A0 批次先行 PoC 验证，未过门槛不得进入 A1 大规模开发。

真实数据还有两点约束：一是 math2 存在 markdown 残留（如 `### 1.`），后端负责清洗，但客户端不得假设输入纯净，仍需按白名单安全渲染 markdown；二是公式与长文混排普遍，渲染组件必须兼容折叠面板与内部滚动。

### 7.2 主案：WebView 封装 + KaTeX 本地离线渲染

- KaTeX（js / css / fonts 全量）打包进 assets，完全离线渲染，零网络依赖。
- 封装 FormulaWebView Composable（AndroidView 桥接）：输入原始文本，输出渲染后的公式混排内容。
- **WebView 对象池**：应用级池默认 3 个实例，启动预热并加载本地模板页；切题时从池中取用、注入新内容、用毕归还。严禁每次切题新建或销毁 WebView，这是帧率达标的关键。
- 高度自适应：模板页内 ResizeObserver 回调内容实际高度，宿主据此设置 AndroidView 高度，避免嵌套滚动冲突。
- 深色模式：注入 CSS 变量切换前景色，WebView 背景透明，杜绝白底闪烁。
- 安全边界：仅加载本地资产，禁用文件访问与任意导航；markdown 只做白名单转换；AI 返回内容永不作为 HTML 渲染（呼应主文档 §9.5）。

### 7.3 备选：Markwon + JLatexMath 原生方案

- 纯原生 TextView 生态绘制，内存占用低，与 LazyColumn 集成自然，无 WebView 冷启动问题。
- Markwon 本身是成熟 markdown 库，混排能力强。
- 主要短板：JLatexMath 对复杂 LaTeX（多行 align、cases、大型矩阵、自定义宏）覆盖度低于 KaTeX，需要逐一验证。

### 7.4 方案对比

| 维度         | 主案 WebView + KaTeX             | 备选 Markwon + JLatexMath |
| :----------- | :------------------------------- | :------------------------ |
| 公式覆盖度   | 高，接近完整 LaTeX 子集          | 中，复杂环境与宏支持有限  |
| 首帧延迟     | 池化热复用后低，冷启动偏高       | 低，原生绘制              |
| 内存         | 较高，每实例数十 MB 级           | 低                        |
| 深色模式     | CSS 注入，易控                   | 原生着色，易控            |
| Compose 集成 | AndroidView 桥接，需处理高度同步 | 原生集成简单              |
| 实现复杂度   | 中（池化 + 桥接）                | 中低                      |
| 主要风险     | 内存与滚动嵌套                   | 公式渲染失败率            |

### 7.5 A0 批次 PoC 门槛（硬性闸门）

样本：从 math1 与 math2 抽取不少于 200 条真实含公式内容，覆盖行内公式、独立公式、分式、根号、上下标、矩阵、分段函数、积分等类别。

门槛指标（主案口径，备选方案重跑同一指标）：

| 指标                       | 门槛                            |
| :------------------------- | :------------------------------ |
| 渲染成功率                 | ≥99%（无 JS 错误、无空白输出） |
| 单题公式首帧（池化热复用） | ≤150ms                         |
| 连续切题 30 次掉帧率       | <5%，滚动维持 60fps             |
| WebView 池内存增量         | ≤150MB                         |
| 深浅色切换                 | 无闪烁、无白底残影              |

判定规则：全部达标则主案转正；任一不达标，书面记录原因并启用备选方案重测，择优落地。PoC 结论与测量数据归档进工程 README，作为 A1 开工前提。

### 7.6 降级链路（无论主备方案都必须实现）

1. 单个公式块渲染异常（JS 错误、800ms 无回调、未知宏报错）：该块退化为原始 LaTeX 纯文本展示。
2. 整题渲染失败：显示"公式渲染失败"占位卡与重试按钮，题干文字部分保持可读。
3. 同一内容连续失败达阈值（如 3 次）：引导用户上报，本地记录 typeCode 与内容哈希用于定位。
4. 任何情况下不得崩溃、不得阻塞切题操作。

### 7.7 Markdown 安全渲染

客户端仅支持白名单内联标记（加粗、斜体、行内代码、换行），一切 HTML 标签转义处理，杜绝注入。清洗责任在后端，防御责任在客户端，两端都做。

## 8. 练习状态机与本地数据策略

### 8.1 状态机定义

每道题维护独立的练习状态，全集为 `loading / idle / editing / submitting / submitted / error`。

| 当前态     | 事件             | 次态                  | 动作                                                 |
| :--------- | :--------------- | :-------------------- | :--------------------------------------------------- |
| loading    | 题目数据就绪     | idle                  | 渲染题干，展示操作栏                                 |
| loading    | 加载失败         | error                 | 展示错误与重试按钮                                   |
| idle       | 用户开始作答     | editing               | 启动草稿防抖写入                                     |
| editing    | 点击确认答案     | submitting            | 生成或复用 client_request_id，禁用输入与按钮         |
| submitting | 服务端成功       | submitted             | 以返回结果为准更新对错与解析，清理草稿与队列项       |
| submitting | 网络失败 / 超时  | error                 | 保留答案入未同步队列，提示稍后重试                   |
| error      | 重试成功         | submitted             | 同提交成功处理                                       |
| error      | 用户继续修改答案 | editing               | 允许改答，提交意图仍沿用原幂等标识直到获得服务端确认 |
| submitted  | 切换下一题       | （新题 loading/idle） | 触发相邻题预取                                       |

补充规则：

- loading 态展示骨架屏而非转圈；切换题目时保留已加载内容，避免闪烁。
- submitting 态按钮文案变为提交中，物理上无法重复触发。
- 主观题 submitted 之后叠加判分子状态（queued / processing / succeeded / failed），见 FR-AN-04。

### 8.2 client_request_id 幂等

- 客户端在首次发起某题提交时生成 UUID 作为 client_request_id，随 `POST /api/attempts` 上送。
- 该题未获得服务端确认结果前，无论重试多少次、答案是否被修改，一律复用同一 ID；服务端按 user_id + client_request_id 幂等去重，保证不重复计分。
- 获得明确成功或明确的业务拒绝（如参数错误）后，该 ID 使命结束；再次发起新一轮作答提交时生成新 ID。

### 8.3 草稿与断网续答

- 作答变更防抖写入 Proto DataStore，键含 user_id、bank_id、question_id 与更新时间。
- 断网时可自由切题、作答、改答，全部落在本地草稿；已点提交但未确认的结果进入未同步队列。
- 网络恢复后自动重放队列中的提交（沿用原 client_request_id），成功后以服务端返回为准刷新本地记录；失败项保留并在刷题页顶部提供"有 N 条记录待同步"横幅。
- 正确性、解析、掌握度、下次复习时间永远以服务端返回为准，客户端本地判定仅作乐观 UI，最终以服务端数据校正。

### 8.4 账号切换与缓存隔离

- 草稿、未同步队列、最近练习上下文全部按 user_id 命名空间隔离。
- 退出登录或切换账号时：清除令牌、销毁内存仓库缓存、删除当前用户命名空间的草稿与队列；题库图片磁盘缓存属公共资源可保留，由 LRU 自然淘汰。
- 账号 A 的草稿在任何情况下不得出现在账号 B 的界面上。

### 8.5 相邻题预取

- 进入第 N 题后，后台静默预取第 N±1 题的详情数据与其图片（限当前练习会话范围内的题目）。
- 禁止预载超出当前练习范围的批量资源（不得整卷拉取全部图片）。
- 预取失败静默忽略，不影响当前题展示；到达列表末页时不越界预取。

## 9. 手势与交互规范

### 9.1 切题手势

- 题目序列由 HorizontalPager 承载，配合预组合保证相邻页就绪。
- 仅响应自屏幕左 / 右边缘起手（边缘判定带宽约 24dp）的横向滑动触发切题，避免与选项点击、文本光标选择、输入框横向滚动冲突。
- 切题转场采用共享轴 X 动效，时长 150~300ms；设置中提供动效开关，开启"减弱动效"后退化为淡入淡出或直切，同时尊重系统"移除动画"无障碍设置。

### 9.2 刷新与返回

- 首页区块、复习列表、统计页支持下拉刷新，刷新期间保留旧数据展示，不闪空白。
- 刷题页存在未提交编辑时，系统返回手势先弹确认对话框："保存草稿并退出 / 继续作答"；已提交或无改动时直接退出。
- 解析视图中未保存的笔记编辑同样纳入返回拦截。

### 9.3 布局与触控底线

| 项目                   | 要求                                                       |
| :--------------------- | :--------------------------------------------------------- |
| 底部操作栏与手势区距离 | ≥80dp，适配全面屏手势条                                   |
| 核心按钮最小点击区     | ≥48dp × 48dp                                             |
| Ripple 反馈            | 所有可点击组件默认 Material3 ripple，不可省略              |
| 错误反馈               | 就地文字提示 + 目标元素轻微 3° 晃动动画，就近给出修正建议 |
| 反馈通道               | 状态表达同时使用文字、图标与颜色，不允许仅靠颜色           |

### 9.4 触感反馈映射

| 场景         | 触感档位     | 说明                 |
| :----------- | :----------- | :------------------- |
| 收藏 / 标记  | LIGHT_IMPACT | 轻触确认感           |
| 提交错误     | WARNING      | 警示感，配合晃动动画 |
| 连续打卡达成 | SUCCESS      | 成功强调感           |

实现层面使用 Compose LocalHapticFeedback 或 HapticFeedbackConstants 对应档位；系统触感关闭时静默降级，不报错。

## 10. AI 拍照纠错模块

### 10.1 全流程

| 步骤   | 内容                                                                                      | 约束                                                        |
| :----- | :---------------------------------------------------------------------------------------- | :---------------------------------------------------------- |
| 1 入口 | 解析视图 / 刷题页"拍照纠错"按钮，携带 bank_id、question_id、attempt_id（可选）            | 未授权相机先进权限流程                                      |
| 2 拍照 | CameraX ImageCapture，取景参考框，拍后进确认预览页                                        | 支持重拍                                                    |
| 3 压缩 | 本地压缩：最长边 ≤1600px、JPEG 质量 80，体积控制在后端限制以内（具体数值以后端契约为准） | IO 线程执行，UI 不卡顿                                      |
| 4 上传 | multipart/form-data 调用`POST /api/ai/feedback` 创建诊断任务                            | 小图可能同步返回结果，大图或模型超时返回 202 与 feedback_id |
| 5 轮询 | `GET /api/ai/feedback/{feedback_id}` 查询状态                                           | 间隔 2s 起、指数退避至上限 5s，总时长上限 60s               |
| 6 展示 | succeeded 渲染结构化诊断卡片                                                              | 见 10.3                                                     |
| 7 兜底 | failed 或超时提供重试上传与自评兜底入口                                                   | 见 10.4                                                     |

### 10.2 权限申请与拒绝引导

- 首次进入流程页申请 CAMERA 权限，申请前展示用途说明前置弹窗（"用于拍摄你的手写答案以进行 AI 诊断"）。
- 用户拒绝后：功能入口保留但置灰，附"去开启"引导按钮；永久拒绝（不再询问）时按钮跳转系统应用设置页。
- 未授权相机不影响 App 其他任何功能。

### 10.3 结构化诊断卡片

- 三要素分区呈现：is_correct（对 / 错大标识，配图标与颜色双通道）、error_reason（中文错误原因正文）、tag_ids 映射出的知识点标签名（Chip 样式；名称来源以后端契约为准，通常随结果返回或经目录数据解析）。
- 卡片下方提供"重做此题"快捷操作。
- raw_response 等原始数据不展示给用户，仅日志留存。

### 10.4 失败重试与自评兜底

- failed、轮询超时、上传失败三种情况均提供"重试"入口；重试上传生成新的诊断任务，原任务状态保留可查。
- AI 判分不可用（连续失败或服务端降级）时，提供"自己判断"兜底入口：用户自行标记对 / 错，随后按普通答题链路提交（走 `POST /api/attempts`，字段以后端契约为准），保证学习闭环不中断。
- 自评结果与 AI 诊断数据互不覆盖，分别留痕。

## 12. 性能要求

| 指标           | 预算                                                    | 说明                      |
| :------------- | :------------------------------------------------------ | :------------------------ |
| 冷启动         | 中端机型 ≤2.5s 到首页可交互                            | 点击图标至首页区块可操作  |
| 进入刷题页     | 缓存命中 ≤300ms 出内容；网络加载 ≤1.5s 出内容或错误态 | 骨架屏过渡                |
| 切题           | 本地已缓存时 ≤200ms 完成内容切换                       | 帧率 60fps，掉帧率 <5%    |
| 提交反馈       | P95 ≤2s 给出成功 / 失败反馈                            | 超时转入 error 态可重试   |
| WebView 池     | 默认 3 实例，总内存增量 ≤150MB                         | 页面销毁时整体释放        |
| 图片磁盘缓存   | LRU 上限 200MB，设置中可手动清理                        | 占位图先行，杜绝白块      |
| 前台常驻内存   | ≤300MB（含 WebView 池）                                | 连续刷题 1 小时无明显增长 |
| APK / AAB 体积 | AAB 下载体积 ≤25MB                                     | 含 KaTeX 本地资源约 1~2MB |

资源纪律：

- 禁止预载超出当前练习范围的任何批量资源（题目、图片均按需 + 相邻预取）。
- 长列表（错题本、笔记、统计明细）使用懒加载组合，不得一次性全量组合。
- 切题不得重复创建重组代价大的对象（WebView、Camera 绑定、重型 ViewModel）。

## 14. 开发批次建议

| 批次 | 内容                                       | 依赖             |
| :--- | :----------------------------------------- | :--------------- |
| A0   | 工程脚手架 + LaTeX 渲染 PoC                | 无               |
| A1   | 登录 + 四 Tab 框架 + 选题库 + 刷题页全题型 | A0 通过 PoC 闸门 |
| A2   | 主观题 AI 判分交互 + 复习错题 + 统计       | A1               |
| A3   | AI 拍照纠错                                | A2               |

### A0：脚手架 + LaTeX PoC

内容：Compose 模板工程、Hilt / Retrofit / DataStore / Navigation 接线、Material3 主题与动态取色基座、CI 与 lint；第 7 章公式渲染 PoC 与门槛判定。

验收标准：

- PoC 五项门槛指标（7.5 节）全部达标，或书面记录不达标原因并完成备选方案同口径重测择优。
- 空壳应用可跑通登录页导航与主题深浅色切换。
- RendererRegistry 启动完整性校验日志机制就绪。

### A1：登录 + 四 Tab + 选题库 + 刷题页全题型

内容：AU、HM、BS 全量功能；PR 页 10 个题型渲染器与作答、提交链路（幂等、草稿、断网续答、预取）、图片懒加载；AN 页基础解析展示。

验收标准：

- 10 个 type_code 注册完整，启动校验无缺失告警；未知 code 注入测试走降级卡不崩溃。
- 登录 → 选题 → 作答 → 提交 → 解析全链路真机走通。
- 断网作答草稿保留，联网自动同步且以服务端结果为准；快速连点确认不产生重复记录。
- math1 / math2 真实题目渲染无白屏无崩溃，公式 PoC 指标在真机复测达标。
- 320dp 宽 + 字体缩放 2.0 + 深色模式组合下核心流程无溢出无裁切。
- 冷启动与切帧率预算（第 12 章）实测达标。

### A2：主观题 AI 判分 + 复习错题 + 统计

内容：主观题判分状态卡与轮询、自评兜底；RV 今日复习、WB 错题本、ST 统计、ME 笔记与退出登录。

验收标准：

- 主观题提交后状态卡正确流转 queued → processing → succeeded / failed；failed 与服务端不可用时自评兜底可完成闭环。
- 复习列表、暂缓、错题本筛选与重做、统计筛选、笔记增改查全部可用且数据与服务端一致。
- 退出登录后草稿与缓存隔离验证通过：账号 A 数据不出现在账号 B。
- 触感映射与转场动效符合第 9 章，且可在设置中关闭。

### A3：AI 拍照纠错

内容：CameraX 拍照、压缩上传、轮询、诊断卡片、权限引导、重试与兜底。

验收标准：

- 权限拒绝与永久拒绝两条路径均有正确引导，其他功能不受影响。
- 拍照到诊断卡全流程在 60s 轮询上限内可完成；压缩产物满足后端限制。
- tag_ids 正确显示为标签名；AI 失败时重试与自评兜底均可用。
- 弱网与超时场景提示明确，全程无崩溃。
