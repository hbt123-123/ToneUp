# ToneUp 数据库结构文档

## 概述

ToneUp 项目使用 SQLite 数据库存储试卷题目数据，按科目和版本拆分为多个 .db 文件。

---

## 表定义

### 1. collections 表 — 试卷集合

**所有科目必需**。存储每套试卷的基本信息。

| 字段  | 类型                | 说明                       |
| ----- | ------------------- | -------------------------- |
| id    | INTEGER PRIMARY KEY | 主键                       |
| year  | INTEGER             | 年份                       |
| title | TEXT                | 标题 (如 "2024年全国甲卷") |

---

### 2. passages 表 — 阅读文章

**仅有示例文章的需要**。存储阅读理解、完形填空等文章正文。

| 字段          | 类型                | 说明                         |
| ------------- | ------------------- | ---------------------------- |
| id            | INTEGER PRIMARY KEY | 主键                         |
| collection_id | INTEGER             | 所属试卷 (→ collections.id) |
| section       | INTEGER             | 试卷部分 (如阅读、完形)      |
| part          | INTEGER             | 部分下的小节                 |
| text_no       | INTEGER             | 文章编号                     |
| content       | TEXT                | 文章正文内容                 |

**使用场景**：英语试卷中，阅读理解/完形填空的文章需要单独存储，题目通过 passage_id 关联。

---

### 3. questions 表 — 题目

**所有科目必需**。存储所有题目。

| 字段             | 类型                | 英语 | 数学 | 说明                                |
| ---------------- | ------------------- | ---- | ---- | ----------------------------------- |
| id               | INTEGER PRIMARY KEY | ✅   | ✅   | 主键                                |
| collection_id    | INTEGER             | ✅   | ✅   | 所属试卷 (→ collections.id)        |
| passage_id       | INTEGER             | ✅   | ❌   | 关联文章 (→ passages.id)，仅英语有 |
| question_type_id | INTEGER             | ✅   | ✅   | 题型 ID                             |
| number           | INTEGER             | ✅   | ✅   | 题号                                |
| content          | TEXT                | ✅   | ✅   | 题干内容                            |
| options          | TEXT                | ✅   | ✅   | 选项 (JSON 格式)                    |
| sub_questions    | TEXT                | ✅   | ✅   | 子题 (复合题/解答题各小问)          |
| answer_text      | TEXT                | ✅   | ✅   | 答案文本                            |
| solution         | TEXT                | ✅   | ✅   | 解析/解答                           |
| score            | INTEGER             | ✅   | ✅   | 分值                                |
| display_order    | INTEGER             | ✅   | ✅   | 显示顺序                            |

**关键差异**：

- 英语有 passage_id，因为大量题型需要关联文章
- 数学无 passage_id，所有题目独立存在

---

### 4. images 表 — 图片

**所有科目可选**。存储题目或文章中的图片。

| 字段          | 类型                | 英语 | 数学 | 说明                         |
| ------------- | ------------------- | ---- | ---- | ---------------------------- |
| id            | INTEGER PRIMARY KEY | ✅   | ✅   | 主键                         |
| collection_id | INTEGER             | ✅   | ❌   | 所属试卷 (→ collections.id) |
| question_id   | INTEGER             | ✅   | ❌   | 关联题目 (→ questions.id)   |
| data          | BLOB                | ✅   | ✅   | 图片二进制数据               |
| mime          | TEXT                | ✅   | ✅   | MIME 类型 (如 "image/png")   |

**关键差异**：

- 英语有外键关联到 collection_id 和 question_id，便于查询
- 数学仅存储图片数据，无外键

---

## 新增数据库模板

新增科目时，参考以下步骤：

### 必需表 (所有科目)

```sql
-- 1. 试卷集合
CREATE TABLE collections (
    id    INTEGER PRIMARY KEY,
    year  INTEGER,
    title TEXT
);

-- 2. 题目
CREATE TABLE questions (
    id               INTEGER PRIMARY KEY,
    collection_id    INTEGER,
    question_type_id INTEGER,
    number           INTEGER,
    content          TEXT,
    options          TEXT,
    sub_questions    TEXT,
    answer_text      TEXT,
    solution         TEXT,
    score            INTEGER,
    display_order    INTEGER
);

-- 3. 图片 (可选，视科目需求)
CREATE TABLE images (
    id   INTEGER PRIMARY KEY,
    data BLOB,
    mime TEXT
);
```

### 可选表

```sql
-- 仅语言类科目需要 (如英语、语文)
-- 用于存储阅读文章
CREATE TABLE passages (
    id            INTEGER PRIMARY KEY,
    collection_id INTEGER,
    section       INTEGER,
    part          INTEGER,
    text_no       INTEGER,
    content       TEXT
);

-- 若添加 passages 表，questions 表需增加字段：
-- passage_id INTEGER  (关联 passages.id)
```

### 索引 (推荐)

```sql
CREATE INDEX idx_questions_cid ON questions(collection_id);
CREATE INDEX idx_passages_cid ON passages(collection_id);
```

## 5. V1.1 数据协议补充

### 5.1 题库清单不等于目录约定

题库业务身份由服务端`manifest.json`维护，数据库文件名和目录层级不参与业务逻辑。当前已有文件包括：`data/math/math1.db`、`data/math/math2.db`、`data/english/english1.db`、`data/english/english2.db`。

每个题库条目至少包含`id`、`subject_id`、`type_id`、`name`、`path`、`schema_version`和`enabled`。用户数据表只保存稳定的`bank_id`，不保存可变的真实路径。

### 5.2 统一读取模型

英语可以有`passages`和`questions.passage_id`，数学可以没有；图片表也可以缺少`collection_id`、`question_id`。后端必须在Repository层转换为统一模型，包含`bank_id`、`question_id`、`collection_id`、`year`、`type_code`、`number`、`content`、可空的`passage`、`options`、`sub_questions`和`display_order`。

`answer_text`和`solution`默认不出现在题目列表接口中，只能在提交结果或明确授权的详情接口中返回。

### 5.3 题型与题目知识点

`question_type_id`必须通过配置映射为稳定的`type_code`，客户端只处理字符串，不直接解释数字ID。增加题目知识点关联表：

```sql
CREATE TABLE question_tags (
    bank_id TEXT NOT NULL,
    question_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    source TEXT NOT NULL DEFAULT 'manual',
    confidence REAL,
    created_at TEXT NOT NULL,
    PRIMARY KEY (bank_id, question_id, tag_id)
);
CREATE INDEX idx_question_tags_tag ON question_tags(tag_id);
```

`source`可取`manual`或`ai`。AI只能从当前学科已有标签中选择，并且写入前必须校验标签存在。

### 5.4 用户库补充表

AI诊断独立存表，不把大段JSON塞进`practice_records`：

```sql
CREATE TABLE ai_feedback (
    id TEXT PRIMARY KEY,
    user_id INTEGER NOT NULL,
    attempt_id INTEGER,
    bank_id TEXT NOT NULL,
    question_id INTEGER NOT NULL,
    status TEXT NOT NULL,
    image_path TEXT,
    is_correct INTEGER,
    error_reason TEXT,
    tag_ids_json TEXT,
    raw_response TEXT,
    error_message TEXT,
    created_at TEXT NOT NULL,
    completed_at TEXT
);
CREATE INDEX idx_ai_feedback_user ON ai_feedback(user_id, created_at);
```

`practice_records`增加`client_request_id TEXT NOT NULL`，并建立唯一索引：

```sql
CREATE UNIQUE INDEX uq_attempt_request
ON practice_records(user_id, client_request_id);
```

`user_mastery`和`user_notes`的唯一业务键应为`user_id + bank_id + question_id`，不能只使用`question_id`。

### 5.5 数据库校验要求

题库导入或重载时必须检查必需表和字段、`options`与`sub_questions`的JSON合法性、`collection_id`关联关系、`display_order`排序能力及图片MIME类型。校验失败的题库不能启用，但不能影响其他题库。
